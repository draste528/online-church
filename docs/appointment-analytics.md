# Аналитика записи к священнику

[SCRUM-40](https://fahhhsino.atlassian.net/browse/SCRUM-40) и раздел 5 [общего контракта](https://fahhhsino.atlassian.net/browse/SCRUM-37).

## События и витрина

Бэкенд вызывает `appointment_events.record(:appointment_id, :event_type)` после изменения заявки и до коммита той же транзакции. Отдельное соединение для вызова использовать нельзя. PostgreSQL подставляет время записи события. Повторный вызов с той же парой UUID и события сохраняет первоначальную запись. Откат транзакции откатывает и событие. Для существующих заявок события задним числом не создаются.

| Счётчик | Что включает |
|---|---|
| `requested` | Созданная заявка |
| `approved` | Переход заявки в «Подтверждена» |
| `rejected` | Переход заявки в «Отклонена» |
| `completed` | Переход заявки в «Завершена» |

Считаются переходы по времени события. Создание и подтверждение одной заявки могут относиться к разным неделям. Неделя начинается в понедельник в 00:00 по Москве и заканчивается в следующий понедельник в 00:00, граница конца исключается. Витрина хранит дату понедельника и четыре счётчика. UUID остаётся в операционной схеме, которая не хранит контакты, тип встречи, заметки или сведения о браузере.

Дата начала покрытия фиксируется один раз командой `enable` после включения записи событий. Первая неполная неделя пропускается. В отчёт входят покрытые недели из восьми последних закрытых календарных недель. В первый час понедельника последний закрытый срез ещё не входит в отчёт. Пустая покрытая неделя содержит четыре нуля и `suppressed: false`. Если хотя бы один счётчик равен 1–4, API скрывает все четыре значения этой недели. Недели выдаются в порядке возрастания.

Пересчёт ждёт коммита или отката активных записей в журнал и публикует срезы одной транзакцией. Повтор сверяет опубликованные значения с журналом. При расхождении команда завершается ошибкой и опубликованные строки сохраняются, чтобы из версий ответа нельзя было вывести малое изменение. Расхождение расследуется по журналам запуска и PostgreSQL. Пропущенный просроченный срез приводит к `503`. До окончания первого полностью покрытого среза включённый отчёт возвращает пустой список.

## Миграция и права

В свежей базе Compose накатывает `analytics/sql/06_appointment_metrics.sql` при инициализации. В существующей базе примените только версионированный файл 06, под владельцем схем с правами DDL. Миграция допускает повторное применение и не очищает данные. Рабочие учётные записи должны иметь разные роли, а владелец объектов не должен использоваться приложениями. Для инсталляции с раздельными ролями привязка выглядит так. Имена заменяются фактическими ролями окружения.

```sql
GRANT USAGE ON SCHEMA appointment_events TO church_backend;
GRANT EXECUTE ON FUNCTION appointment_events.record(uuid, text) TO church_backend;

GRANT USAGE ON SCHEMA appointment_metrics TO church_backend, church_appointment_etl;
GRANT EXECUTE ON FUNCTION appointment_metrics.summary() TO church_backend;
GRANT EXECUTE ON FUNCTION appointment_metrics.enable(), appointment_metrics.refresh() TO church_appointment_etl;
```

Основному API нужны его существующие права на пользователей для проверки JWT и роли. Для выдачи отчёта достаточно вызова `summary()`. Права на чтение таблиц журнала и витрины прикладным ролям не выдаются. У отдельного HTTP-сервиса аналитики на порту 8000 нет маршрута или роли БД для отчёта.

## Запуск и контроль

1. Задайте `APPOINTMENTS_ETL_DATABASE_URL` через секреты окружения с учётной записью ETL и убедитесь в доступности миграции.
2. После включения транзакционного вызова `record` в бэкенде один раз выполните `python -m analytics.src.loaders.appointment_metrics enable`. Зафиксируйте время из вывода как начало покрытия. Повтор команды вернёт то же время.
3. Включите Airflow DAG `church_appointments_weekly`. Он запускается по понедельникам в 01:00 `Europe/Moscow`. В окружении worker должны быть репозиторий в `PYTHONPATH`, SQLAlchemy и драйвер PostgreSQL из контейнера аналитики. Если Airflow не развёрнут, поставьте ту же команду `python -m analytics.src.loaders.appointment_metrics refresh` на это расписание. Она годится и для ручного восстановления после сбоя. Вывод показывает число новых срезов, при повторе без изменений это 0. Ошибка команды означает, что транзакция пересчёта не зафиксирована.
4. Проверяйте успех задания и HTTP `200` с администраторским токеном после срока публикации. На тестовом стенде сверяйте край недели, скрытые группы и пустую неделю. Исходный журнал хранится 90 дней с момента события. Удаление старых строк при необходимости выполняет владелец журнала по регламенту окружения, сохраняя весь интервал последних восьми закрытых недель. Приложение и ETL журнал не очищают.

В публичном окружении база и внутренний сервис аналитики должны быть доступны только в закрытой сети. Демонстрационные учётные данные из Compose подходят для разработки. Для выпуска проверяются внешние правила доступа к портам 5432 и 8000 и защита прежнего отчёта регистраций. Изменения контракта и формул регистраций ведутся по [SCRUM-33](https://fahhhsino.atlassian.net/browse/SCRUM-33).

PYTHONPATH=. python -m pytest -q backend/tests/test_appointment_analytics.py
